* Neural Network Architecture Analysis (ac_solver/agents/ppo_agent.py)

** Fully Connected Layers (MLP)
The project uses Multi-Layer Perceptrons (MLPs) defined in `ac_solver/agents/ppo_agent.py`.
- **Initialization**: Orthogonal Initialization (`std=sqrt(2)` for hidden, `0.01` for actor head, `1.0` for critic head) with constant bias `0.0`.
- **Activation**: `nn.Tanh()` is used for hidden layers.

** Network Topology
The architecture is dynamically determined by the `nodes_counts` argument (default: `[256, 256]`).
- **Input_Dim**: Flattened observation vector size (`num_relators * max_relator_length`).
- **Hidden Layers**: Defined by `nodes_counts`.
- **Output**:
  - **Critic**: Outputs a scalar value $V(s)$.
  - **Actor**: Outputs logits for the action space (size 12).

** Implementation Details (`Agent` class)
- **Critic**: `nn.Sequential` constructed via `build_network`.
- **Actor**: Split into two parts to facilitate interpretability:
  - `actor_body`: Feature extractor (Input -> Hidden Layers -> Tanh).
  - `actor_head`: Final linear layer (Hidden -> Logits).

* PPO Training & Algorithm Details (ac_solver/agents/)

** Training Loop (`training.py`)
The `ppo_training_loop` implements the Proximal Policy Optimization algorithm.
- **Rollout**: Collects `num_steps` of data across `num_envs` parallel environments.
- **Advantage Estimation**: Uses Generalized Advantage Estimation (GAE).
- **Optimization**:
  - **Policy Loss**: Supports both **Clipped Surrogate Objective** (`is_loss_clip=True`) and **KL-Penalty** (`is_loss_clip=False`).
  - **Value Loss**: Mean Squared Error, optionally clipped (`clip_vloss`).
  - **Entropy Bonus**: Encourages exploration.

** Learning Rate Schedule
Implemented in `get_curr_lr` (`training.py`):
- Supports **Linear** and **Cosine** decay.
- Includes a **Warmup Period** (`warmup_period`) where LR increases linearly from 0.
- Can anneal to a fraction of the max LR (`min_lr_frac`).

** Curriculum & State Management
The agent does not train on a single static environment but a set of presentations.
- **Initialization**: `get_env` (`environment.py`) loads initial states from text files (solved or all).
- **State Selection Logic** (`training.py`):
  1. **Round 1**: Iterates through all loaded initial states at least once.
  2. **Subsequent Rounds**: Probabilistically selects between:
     - **Unsolved States**: To encourage solving new problems.
     - **Solved States**: To prevent catastrophic forgetting (controlled by `repeat_solved_prob`).
- **Success Recording**: Tracks solved/unsolved states and the history of moves (`ACMoves_hist`).

* Mechanistic Interpretability via SAE

** Feature Steering Logic
SAE (Sparse Autoencoder) allows steering the solver's intuition.
1. Extract activations $f$ from `actor_body` using `agent.get_actor_activations(x)`.
2. Map $f$ to sparse features $z$.
3. Perturb specific features $z_i$.
4. Reconstruct $f'$ and pass to `actor_head`.

** Why Target the Actor?
- The Actor determines the policy. Interpreting it reveals the "reasoning" behind specific moves.
- The split architecture (`body` vs `head`) in `ppo_agent.py` is specifically designed for this.

* Environment Implementation Details (ac_solver/envs & agents/environment.py)

** Core Environment (`ac_env.py`)
- **State**: Box space, flattened array of relators.
- **Action**: Discrete(12), representing AC moves.
- **Reward**: Step penalty + large sparse reward for solving.

** Wrappers & Vectorization (`agents/environment.py`)
- **Vectorization**: Uses `gym.vector.SyncVectorEnv` to run `num_envs` in parallel.
- **Wrappers**:
  - `NormalizeReward`: Normalizes rewards using running mean/std (optional).
  - `TransformReward`: Clips rewards to a specified range (optional).
- **Configuration**: `make_env` helper function configures the environment based on arguments.

* Search Algorithms Analysis (ac_solver/search/)

** Search Space Challenges
- Branching factor of 12 leads to exponential growth ($12^d$).
- Practical search depth is limited to 3-5 steps.

** Algorithms
- **BFS**: Guarantees shortest path but limited by memory/time.
- **Greedy (Best-First)**: Uses heuristic (length) to find solutions deeper in the tree, but no optimality guarantee.

* Miller-Schupp Series
- Hard instances used for testing.
